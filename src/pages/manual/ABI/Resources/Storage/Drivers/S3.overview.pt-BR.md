# S3

`S3` é o driver do Storage para o Amazon S3 e serviços compatíveis com S3 (MinIO, Cloudflare R2,
Wasabi). Além do contrato do [Storage](/guide/storage/overview/) que todo disk compartilha, ele
tem três coisas só dele, para bytes que não devem passar pelo seu servidor:

- **URLs pré-assinadas** — um link que deixa alguém ler ou escrever um objeto por um tempo
  limitado, sem credenciais;
- **o handle `Uploads`** — um Multipart Upload cujas partes o navegador envia direto para o
  bucket;
- **leituras por faixa** — uma janela de um objeto em vez dele inteiro.

Elas existem só no S3: acesse-as no próprio driver, não na fachada `Storage`.

Quando os bytes passam pelo seu servidor — uma parte que ele monta ou recebe — o mesmo handle
envia essa parte por conta própria. E toda chamada deixa o que deu errado em `$S3->Failure`, para
o código que precisa decidir o que fazer em seguida: tentar de novo, responder `404` ou desistir.

```php
use Bootgly\ABI\Resources\Storage;

$Storage = new Storage([
   'disks' => [
      'media' => [
         'driver' => 's3',
         'root'   => 'uploads',      // todo path abaixo fica dentro deste prefixo
         'bucket' => 'assets',
         'region' => 'us-east-1',
         'key'    => '…',
         'secret' => '…',
      ],
   ],
]);

/** @var Storage\Drivers\S3 $S3 */
$S3 = $Storage->open('media');
```

Todo método abaixo retorna `false` quando é recusado ou falha, deixa o motivo em `$S3->error` e
o que deu errado — o status, o código de erro do serviço, o tipo de falha — em `$S3->Failure` (veja
[Decidir a partir de uma falha](#decidir-a-partir-de-uma-falha)).
Abrir o disco é a exceção: lança `InvalidArgumentException` quando `key`, `region`, `service` ou
`token` contém um espaço ou um caractere de controle — uma quebra de linha no fim de um arquivo
de segredos, por exemplo — porque esses valores vão para o cabeçalho `Authorization` e para a
query string.

## Um link de download com prazo

```php
$URL = $S3->presign('GET', 'invoices/2026-11.pdf', 300);
// https://assets.s3.us-east-1.amazonaws.com/uploads/invoices/2026-11.pdf?X-Amz-Algorithm=…

if ($URL === false) {
   // $S3->error diz o motivo
}
```

Quem abrir a URL nos próximos 300 segundos baixa aquele objeto — sem sessão, sem credenciais, sem
requisição passando pela sua aplicação. O `presign()` não faz requisição nenhuma: ele só assina.

Para o navegador salvar o arquivo com um nome, ou para fixar o tipo, passe os overrides de
resposta. Eles são assinados junto com a URL, então quem a recebe não consegue alterá-los:

```php
$URL = $S3->presign('GET', 'invoices/2026-11.pdf', 300, [
   'response-content-disposition' => 'attachment; filename="invoice.pdf"',
   'response-content-type' => 'application/pdf',
]);
```

Um `PUT` pré-assinado deixa quem tem a URL gravar um objeto em uma única requisição:

```php
$URL = $S3->presign('PUT', 'avatars/42.png', 60);
```

Uma URL assinada assim cobre o método, o objeto e o prazo — não o que é enviado: quem tem a URL
escolhe os bytes, o tamanho e o `Content-Type`. Para decidi-los no servidor, vincule-os no quinto
argumento:

```php
$URL = $S3->presign('PUT', 'avatars/42.png', 60, [], [
   'Content-Type' => 'image/png',
   'Content-Length' => 204800,                        // exatamente esta quantidade de bytes
   'Content-MD5' => base64_encode(md5($bytes, true)), // exatamente estes bytes
   'x-amz-meta-owner' => '42',
]);
```

Cada header vinculado é assinado junto com a URL: o upload precisa trazê-lo exatamente com aquele
valor, ou o serviço o recusa. Vincule só o que precisar — qualquer subconjunto funciona:

| Header | O que fixa | O que o cliente envia |
|---|---|---|
| `Content-Length` | O tamanho do corpo, em bytes. | Nada a mais: o navegador o define a partir do corpo. |
| `Content-Type` | O tipo com que o objeto é gravado. | O mesmo header `Content-Type`. |
| `Content-MD5` | Os próprios bytes — o base64 do MD5 deles. | O mesmo header `Content-MD5`. |
| `x-amz-meta-*` | Uma entrada de metadados do objeto. | O mesmo header, com o mesmo valor. |

A partir de um navegador, `Content-MD5`, `x-amz-meta-*` e um `Content-Type` como `image/png` são
headers de requisição que a própria página define, então a regra de CORS do bucket precisa
listá-los nos headers permitidos. O `Content-Length` não exige nada.

> [!WARNING]
> Uma URL de `PUT` sem nada vinculado é um cheque em branco para um objeto: quaisquer bytes, de
> qualquer tamanho e tipo. Entregue-a só a código em que você confia, ou vincule ao menos
> `Content-Length` e `Content-Type`. Para um arquivo grande, use o handle `Uploads` abaixo.

### O que é uma URL pré-assinada

Uma URL pré-assinada é um segredo que funciona até expirar. Qualquer um que a leia — em um log,
em um referrer, em uma captura de tela compartilhada — pode usá-la. Então:

- mantenha o prazo curto: segundos ou minutos, nunca o máximo de 7 dias por hábito;
- nunca a registre em log, nem a coloque em uma mensagem de erro ou exceção;
- entregue-a ao cliente que a pediu, por HTTPS, e a mais ninguém.

Uma URL não pode ser revogada individualmente: ela para de funcionar quando expira, ou quando a
chave de acesso que a assinou é desativada.

O que ela autoriza é estreito por construção:

| | |
|---|---|
| **Método** | `GET`, `HEAD` ou `PUT` — aquele para o qual foi assinada. Apagar, listar e as etapas do multipart nunca são pré-assinados aqui. |
| **Objeto** | Aquele único path, resolvido dentro do `root` do disk como qualquer outra operação. `../` não sai do prefixo, e o próprio root é recusado. |
| **Prazo** | De 1 a 604800 segundos (7 dias), contados pelo serviço a partir do momento da assinatura. |
| **Query** | Só os seis overrides `response-*`, em `GET`/`HEAD`. Qualquer outra coisa — um sub-recurso, um parâmetro `x-amz-*` — é recusada. |
| **Headers** | Só `Content-Type`, `Content-Length`, `Content-MD5` e `x-amz-meta-*`, em `PUT`. Qualquer outra coisa — uma ACL, uma origem de cópia — é recusada. O Amazon S3 também rejeita um header `x-amz-*` que a URL não assinou; confira se o seu serviço compatível com S3 faz o mesmo. |

## Upload do navegador direto para o bucket

Um arquivo grande não precisa passar pelo seu servidor. O servidor abre um Multipart Upload,
assina uma URL por parte, o navegador faz o `PUT` de cada parte no bucket, e o servidor as junta.

O handle é `$S3->Uploads`. Ele não guarda estado: um upload atravessa várias requisições, então
toda etapa recebe o path do objeto e o id do upload.

**1. Abra o upload** — o servidor decide o path, o tipo e os metadados:

```php
$id = $S3->Uploads->create('videos/42/source.mp4', [
   'type' => 'video/mp4',
   'meta' => ['owner' => '42'],
]);
// guarde o $id junto do seu próprio registro do upload e então envie-o ao cliente
```

**2. Assine cada parte** — conforme o cliente as pede:

```php
$URL = $S3->Uploads->sign('videos/42/source.mp4', $id, $part, 900);   // $part: 1..10000
```

O cliente envia os bytes daquela parte com um `PUT` simples para a URL — nenhum header é
necessário. Uma parte enviada de novo substitui a anterior, então uma parte que falhou é
simplesmente reenviada.

Para fixar o tamanho de uma parte — ou os bytes dela — vincule-os, como em um `PUT`
pré-assinado:

```php
$URL = $S3->Uploads->sign('videos/42/source.mp4', $id, $part, 900, [
   'Content-Length' => 8 * 1024 * 1024,   // esta parte tem exatamente 8 MiB
]);
```

Uma parte vincula só `Content-Length` e `Content-MD5`: o tipo e os metadados foram definidos no
`create()`. A última parte costuma ser menor, então o cliente informa quantos bytes vai enviar
e o servidor decide se aquele tamanho é aceitável antes de assinar.

**3. Confira o que chegou e então complete:**

```php
$Parts = $S3->Uploads->list('videos/42/source.mp4', $id);
// [1 => ['etag' => '"9b2c…"', 'size' => 8388608], 2 => […], …] — ou false

$size = 0;
foreach ($Parts ?: [] as $Part) {
   $size += $Part['size'];
}

if ($Parts === false || $Parts === [] || $size > 2_000_000_000) {
   $S3->Uploads->abort('videos/42/source.mp4', $id);
}
else {
   $S3->Uploads->complete('videos/42/source.mp4', $id, $Parts);
}
```

O `list()` é o que o serviço realmente tem: os tamanhos são medidos pelo serviço, não informados
por quem enviou, e os ETags são os que o `complete()` precisa. Completar a partir do `list()`
significa que o navegador nunca precisa ler um header de resposta, então as regras de CORS do
bucket só precisam permitir o `PUT` — mais o `Content-MD5` como header permitido, quando uma parte o
vincula.

**Retomar** — o `list()` também é como um upload interrompido continua: as partes que já estão
lá não precisam ser enviadas de novo.

**Abortar** — um upload que nunca é completado mantém suas partes, e o serviço cobra por elas.
Chame `abort()` quando o usuário cancelar ou uma conferência falhar, e configure no bucket uma
regra de ciclo de vida que aborte uploads incompletos depois de alguns dias, para os que ninguém
cancela.

> [!IMPORTANT]
> Trate o id do upload como parte do seu próprio estado. Guarde-o no servidor junto do registro
> a que ele pertence (quem começou, qual path), e tire o path desse registro — nunca da
> requisição. O handle recusa um id que não seja um token simples, mas não tem como saber de
> quem é o upload.

### Notas para serviços compatíveis com S3

- **Partes de tamanho igual.** O Amazon S3 só exige que toda parte, menos a última, tenha pelo
  menos 5 MiB. O Cloudflare R2 exige também que toda parte, menos a última, tenha o **mesmo**
  tamanho, e recusa a conclusão caso contrário. Escolha um tamanho de parte no cliente (8 ou
  16 MiB, por exemplo), corte o arquivo em partes exatamente desse tamanho, e confira os tamanhos
  no `list()` antes de completar — ou vincule o `Content-Length` ao assinar cada parte, para que
  nenhum outro tamanho possa ser enviado.
- **Endpoints `http`.** Um disk cujo `endpoint` é `http://…` (um MinIO local, um fake de teste) é
  recusado na construção, a menos que defina `'insecure' => true`, e suas URLs pré-assinadas
  também são `http`: a URL — um segredo — e os bytes trafegam em texto claro. Use só em
  desenvolvimento.

## Enviar uma parte do servidor

Algumas partes não estão no navegador: uma parte que a sua aplicação monta (um cabeçalho, um
trecho recodificado), ou uma que chegou ao seu servidor de qualquer forma. O `put()` envia uma
parte de um upload aberto por conta própria e retorna o ETag dela:

```php
$ETag = $S3->Uploads->put('videos/42/source.mp4', $id, 3, $bytes);
// '"9b2c…"' — ou false: $S3->error e $S3->Failure dizem por quê
```

O upload é o que o `create()` abriu: partes do servidor e partes do navegador podem preencher o
mesmo upload, em qualquer ordem, e o `complete()` as junta a partir do `list()` como antes — ou
a partir dos ETags que o `put()` retornou:

```php
$S3->Uploads->complete('videos/42/source.mp4', $id, [
   1 => ['etag' => $first],
   2 => ['etag' => $second],
]);
```

Alguns pontos para ter em mente:

- **Memória.** `$bytes` é uma string: a parte inteira fica na memória enquanto é enviada. Mantenha
  as partes em poucos MiB (8 ou 16 MiB é o comum); uma parte tem no máximo 5 GiB.
- **Tamanho.** Toda parte, menos a última, precisa ter pelo menos 5 MiB. O serviço não confere
  isso quando a parte chega, e sim no `complete()`, que falha com `EntityTooSmall` em
  `$S3->Failure->code`. No Cloudflare R2, toda parte menos a última também precisa ter o mesmo
  tamanho.
- **Novas tentativas.** Uma parte enviada de novo substitui a anterior, então uma parte que falhou
  é simplesmente enviada de novo — quando o `$S3->Failure` diz que vale a pena (abaixo).
- **Recusas.** Um upload id que não é um token simples, um número de parte fora de 1..10000, a
  raiz do disk como path e um corpo acima de 5 GiB são recusados sem requisição.

## Ler uma janela de um objeto

O `read()` recebe um offset e um tamanho depois do sink:

```php
$Sink = fopen('php://memory', 'r+');

$S3->read('videos/42/source.mp4', $Sink, 0, 1024);          // os primeiros 1024 bytes
$S3->read('videos/42/source.mp4', $Sink, 1_048_576, 4096);  // 4096 bytes a partir do offset 1 MiB
$S3->read('videos/42/source.mp4', $Sink, 1_048_576);        // do offset 1 MiB até o fim
```

O sink nunca recebe um byte de fora da janela:

- uma janela que passa do fim do objeto é cortada no fim;
- um offset no fim ou depois dele é `false` (`range not satisfiable (HTTP 416)`), sem nada
  escrito;
- um endpoint que ignora a faixa e responde o objeto inteiro, ou responde outra janela, é
  `false`, sem nada escrito — nunca os bytes errados no sink.

Uma janela ainda pode ser cortada no caminho: a conexão cai, ou a resposta termina antes do
último byte. O `read()` então é `false` com os primeiros bytes da janela já no sink. Quando você
anexa janelas a um arquivo, anote a posição do sink antes de cada `read()` e trunque de volta
para ela em caso de `false`, antes de tentar de novo:

```php
$position = ftell($Sink);

if ($S3->read('videos/42/source.mp4', $Sink, $offset, $length) === false) {
   ftruncate($Sink, $position);
   fseek($Sink, $position);
   // tente de novo, ou desista — $S3->error diz o motivo
}
```

Sem offset e sem tamanho, o `read()` é a leitura do objeto inteiro que todo driver tem. A janela
faz parte só do `S3::read()`: o `Storage::read()` e os outros drivers continuam com
`read($path, $sink)`.

## Decidir a partir de uma falha

O `$S3->error` é uma frase para um log. O `$S3->Failure` é a mesma falha como dado, para o código
que decide:

```php
use Bootgly\ABI\Resources\Storage\Drivers\S3\Failure\Kinds;

if ($S3->read('invoices/2026-11.pdf', $Sink) === false) {
   $Failure = $S3->Failure;

   if ($Failure->code === 'NoSuchKey') {
      // o objeto não existe: responda 404
   }
   else if ($Failure->kind === Kinds::Transport || $Failure->status >= 500 || $Failure->code === 'SlowDown') {
      // o serviço estava inacessível ou ocupado: tente mais tarde
   }
   else {
      // recusado (acesso, requisição inválida): registre $S3->error e pare
   }
}
```

Uma falha tem quatro campos:

| Campo | O que guarda |
|---|---|
| `status` | O status HTTP da resposta; `0` quando nenhuma resposta chegou, ou quando nada foi enviado. |
| `code` | O código de erro do serviço — `NoSuchKey`, `AccessDenied`, `SlowDown`, `EntityTooSmall`, … — ou `''` quando ele não deu nenhum. Uma resposta a `HEAD` não tem corpo, então um `check()`, `measure()` ou `inspect()` que falhou tem status e não tem código. |
| `kind` | `Transport`: nenhuma resposta completa — o endpoint recusou a conexão, derrubou-a, estourou o tempo ou cortou o corpo. `Protocol`: uma resposta que não é a que o S3 dá — sem ETag, sem upload id, outra faixa que não a pedida, uma resposta grande demais para ser do S3. `Refusal`: o serviço disse não — qualquer outro status, ou um `<Error>` dentro de um `200` — ou o driver recusou uma entrada antes de enviá-la (status `0`). |
| `message` | O motivo da requisição que falhou, por extenso. O `$S3->error` diz o resultado da chamada inteira e pode dizê-lo de outro jeito: o `clear()` diz que um ou mais deletes falharam, e uma requisição que o driver não conseguiu assinar termina como `HTTP 0` lá. |

Ela nunca guarda a requisição, as credenciais nem a `<Message>` do próprio serviço: um corpo de
erro pode ecoar a requisição assinada, então só o código é mantido — e só quando tem cara de
código (letras, dígitos e pontos, no máximo 64).

Quando ela é preenchida:

- **Depois de cada chamada.** O `$S3->Failure` é `null` depois de uma chamada que deu certo, e
  toda chamada começa limpa. O `check()` de uma chave que não existe é `false` sem falha: um `404`
  é uma resposta.
- **A primeira requisição que falhou.** Uma chamada feita de várias requisições — um `write()`
  grande, um `move()`, um `clear()` — aponta a primeira que falhou: a parte recusada, não o abort
  que veio depois dela; o primeiro delete recusado, mesmo que os seguintes tenham dado certo.
- **Por Fiber.** Requisições atendidas ao mesmo tempo em um disk, cada uma na sua Fiber, leem
  cada uma a sua falha, mesmo com outra Fiber no meio de uma chamada. Leia logo depois da chamada,
  antes da próxima chamada naquele disk na mesma Fiber.
- **Chamadas dentro de uma chamada.** Uma chamada feita no disk de dentro de uma das chamadas dele
  — a partir de um stream que o disk está lendo ou escrevendo — pertence àquela chamada: a falha
  dela é a da chamada de fora, mesmo quando a de fora dá certo. Os listeners de eventos do Storage
  não ficam dentro da chamada: o facade os roda depois dela, pelo `preserve()`, e devolve à chamada
  o `$error` e o `$Failure` dela.

## Montar e ler requisições por conta própria

O driver envia as requisições por um socket bloqueante. Outro transporte — um cliente HTTP em um
event loop — pode enviar exatamente as mesmas requisições: o `S3\Writer` as monta, o `S3\Reader`
lê as respostas. Nenhum dos dois toca na rede.

```php
use Bootgly\ABI\Resources\Storage\Drivers\S3\Operations;
use Bootgly\ABI\Resources\Storage\Drivers\S3\Reader;
use Bootgly\ABI\Resources\Storage\Drivers\S3\Writer;

$Writer = new Writer('uploads', $options);     // o root e as opções do disk

[$URI, $headers] = $Writer->compose('GET', $Writer->locate('invoices/2026-11.pdf'), [], '', []);
// Envie "GET {$URI}" com $headers — Host incluído — para $Writer->host na $Writer->port,
// por TLS com as opções $Writer->secure quando não forem null. Depois, com a resposta:

$Failure = Reader::judge(Operations::GetObject, $status, $answer, $body, "S3 GET {$URI}");
// null: o objeto está no corpo; senão, a mesma Failure que o driver daria
```

O `compose()` assina exatamente o que o driver assina, então o serviço vê um único cliente. O
writer lê as opções como o driver lê — o endpoint, o estilo de endereçamento, o prefixo, a regra
do `insecure` — e guarda as credenciais por dentro: um dump dele mostra para onde aponta, nunca a
key nem o secret.

## Assinar requisições por conta própria

O driver assina com o `Storage\Drivers\S3\Signer`, um assinador AWS Signature Version 4 que você
pode usar sozinho — para chamar uma operação do S3 que o driver não encapsula, ou outro serviço
que aceite a mesma assinatura:

```php
use Bootgly\ABI\Resources\Storage\Drivers\S3\Signer;

$Signer = new Signer($key, $secret, 'us-east-1');

// Header auth: os headers a enviar com a requisição
$headers = $Signer->sign(
   'GET',
   'assets.s3.us-east-1.amazonaws.com',
   '/uploads/a%20b.txt',                 // já percent-encoded
   ['versionId' => '3'],                 // raw: codificado e ordenado pelo assinador
   ['Range' => 'bytes=0-9'],             // assinado, e enviado por você
   hash('sha256', '')                    // o SHA-256 do corpo
);

// Query auth: a query string de uma URL pré-assinada
$query = $Signer->presign('GET', 'assets.s3.us-east-1.amazonaws.com', '/uploads/a%20b.txt', [], 300);
$URL = "https://assets.s3.us-east-1.amazonaws.com/uploads/a%20b.txt?{$query}";
```

O assinador assina o que recebe: diferente do `S3::presign()`, ele não tem prefixo de root nem
lista de métodos ou parâmetros permitidos. Ele lança `InvalidArgumentException` para entrada que
não é canônica — uma quebra de linha no método, no host, no path, em um header ou no hash do
payload, um `?` no path, um prazo fora de 1..604800, um parâmetro de autenticação `X-Amz-*` na
query. Valores de query são dados: o que eles tiverem é percent-encoded.

## Referência

### S3

```php
public function presign (string $method, string $path, int $expires, array $query = [], array $headers = []): string|false
```

Pré-assina uma requisição para um objeto e retorna sua URL absoluta, sem fazer requisição.
`$method` é `GET`, `HEAD` ou `PUT`; `$expires` é o prazo em segundos, 1..604800
(`Signer::LIFETIME`); `$query` recebe os overrides `response-content-disposition`,
`response-content-type`, `response-cache-control`, `response-content-encoding`,
`response-content-language` e `response-expires` de um `GET`/`HEAD`, como strings; `$headers`
recebe o que um `PUT` precisa enviar — `Content-Type`, `Content-Length`, `Content-MD5` e
`x-amz-meta-*`, cada um uma vez, como string ou inteiro.
Retorna `false` — motivo em `$error` — para qualquer outro método, parâmetro ou header, um
valor de header vazio ou malformado, um prazo fora do intervalo, o root do disk como path, ou um
disk sem `key`/`secret`.

```php
public function read (string $path, $sink, int $offset = 0, null|int $length = null): bool
```

Transmite o objeto — ou a janela de `$length` bytes a partir de `$offset` — para o resource
gravável `$sink`. Um tamanho `null` lê até o fim. Retorna `false` para um offset negativo, um
tamanho menor que 1, um objeto inexistente, um offset no fim ou depois dele, ou uma resposta que
não é a janela pedida — sem nada escrito, quando uma janela foi pedida — e para uma janela
cortada no caminho, com os primeiros bytes já escritos.

```php
public private(set) Uploads $Uploads
```

O handle de Multipart Upload do disk.

```php
public null|Failure $Failure
```

A falha da última chamada feita no disk na Fiber atual (ou fora de qualquer Fiber): `null` depois
de uma chamada que deu certo. Uma chamada feita de várias requisições aponta a primeira que
falhou. Somente leitura.

```php
public function preserve (Closure $Work): void
```

Roda `$Work` e devolve ao disk o resultado da chamada feita antes dele: o `$error` e o `$Failure`
leem depois do `$Work` o que liam antes. O facade do Storage roda os listeners de eventos aqui. O
`$Failure` volta na Fiber atual; o `$error` é um por disk, compartilhado por todas as Fibers, então
código concorrente lê o `$Failure`.

### S3\Uploads

```php
public function create (string $path, array $options = []): string|false
```

Inicia um Multipart Upload para o objeto e retorna o id do upload. `$options` são as opções de
escrita: `type` (Content-Type) e `meta` (um mapa `x-amz-meta-*`).

```php
public function sign (string $path, string $id, int $part, int $expires, array $headers = []): string|false
```

Pré-assina o `PUT` de uma parte (1..10000, `Uploads::PARTS`) daquele upload e retorna sua URL,
sem fazer requisição. `$expires` é o prazo em segundos, 1..604800 (`Signer::LIFETIME`);
`$headers` recebe o que o `PUT` precisa enviar — `Content-Length` e `Content-MD5`, cada um uma
vez. Retorna `false` para qualquer outro header.

```php
public function put (string $path, string $id, int $part, string $body): string|false
```

Envia a parte `$part` (1..10000) do upload com `$body` como bytes e retorna o ETag dela, como o
serviço enviou (entre aspas). A parte substitui qualquer anterior com o mesmo número. Retorna
`false` para um upload id ou número de parte inválido, a raiz do disk como path, um corpo acima de
5 GiB ou uma requisição que falhou — motivo em `$error`, detalhes em `$Failure`. O handle que o
driver monta sempre tem esse passo; um handle montado à mão sem ele lança `LogicException`.

```php
public function list (string $path, string $id): array|false
```

Lista todas as partes que o serviço tem para o upload, seguindo todas as páginas:
`[número => ['etag' => string, 'size' => int]]`, em ordem crescente. Retorna `false` quando
qualquer página falha ou está malformada — nunca uma lista parcial.

```php
public function complete (string $path, string $id, array $parts): bool
```

Junta as partes no objeto. `$parts` é o que o `list()` retorna, ou `[número => ['etag' => …]]`
montado com os ETags que quem enviou recebeu. Uma conclusão que falha deixa o upload aberto:
complete de novo, ou aborte.

```php
public function abort (string $path, string $id): bool
```

Aborta o upload e libera suas partes. Um upload que o serviço não conhece mais conta como
abortado.

```php
public const int PARTS = 10000;
```

O máximo de partes que um upload comporta, e o maior número de parte.

### S3\Failure

```php
public private(set) int $status
```

O status HTTP da resposta; `0` quando nenhuma resposta chegou ou nada foi enviado.

```php
public private(set) string $code
```

O código de erro do serviço (`NoSuchKey`, `AccessDenied`, `SlowDown`, …); `''` quando ele não deu
nenhum, ou deu algo que não é um código.

```php
public private(set) Failure\Kinds $kind
```

`Transport`, `Protocol` ou `Refusal`.

```php
public private(set) string $message
```

O motivo da requisição que falhou, por extenso. O `$error` diz o resultado da chamada inteira e
pode dizê-lo de outro jeito (um passo seguinte que também falhou, ou o `HTTP 0` de uma requisição
que não pôde ser assinada).

### S3\Failure\Kinds

```php
enum Kinds { case Transport; case Protocol; case Refusal; }
```

Como uma requisição falhou: nenhuma resposta completa (`Transport`), uma resposta que não é a que
o S3 dá (`Protocol`), ou um não do serviço ou do próprio driver (`Refusal`).

### S3\Operations

```php
enum Operations
```

As operações S3 que o driver envia, cada uma com as suas respostas de sucesso para o
`Reader::judge()`: `PutObject`, `GetObject`, `HeadObject`, `DeleteObject`, `CopyObject`,
`ListObjectsV2`, `CreateMultipartUpload`, `UploadPart`, `ListParts`, `CompleteMultipartUpload`,
`AbortMultipartUpload`.

### S3\Reader

```php
public static function judge (Operations $Operation, int $status, array $headers, string $body, string $subject, null|array $window = null): null|Failure
```

`null` quando a resposta é o sucesso de `$Operation`, senão a falha dela. `PutObject`,
`CreateMultipartUpload` e `UploadPart` dão certo com qualquer `2xx`; `CopyObject` e
`CompleteMultipartUpload` com um `2xx` sem `<Error>`; `GetObject` com um `200` — ou, com uma
`$window` (`[offset, length]`), um `206` dessa janela; `HeadObject`, `ListObjectsV2` e `ListParts`
com um `200`; `DeleteObject` e `AbortMultipartUpload` com `200`, `204` ou um `404` que diz que o
que sumiu sumiu (corpo vazio ou em branco, `NoSuchKey`, `NoSuchUpload`) — nunca outro `404` (`NoSuchBucket`, a
página de um proxy). Os `$headers` têm nomes em minúsculas; `$subject` abre a mensagem (`S3 GET /bucket/key`).

```php
public static function identify (string $body, string $subject): string|Failure
```

O upload id de uma resposta a `CreateMultipartUpload`, ou uma falha `Protocol`.

```php
public static function tag (array $headers, string $subject): string|Failure
```

O ETag de uma resposta a `UploadPart`, como veio, ou uma falha `Protocol` quando ele falta ou não
poderia ser devolvido ao `complete()`.

```php
public static function index (string $body, array $followed, string $subject): array|Failure
```

Uma página de `ListObjectsV2`: `[keys, next]`, em que `next` é o próximo continuation token, `''`
na última página, ou uma falha `Protocol` quando a página não avança (sem token, ou um que está em
`$followed`). Um corpo que não é uma listagem é uma falha `Protocol`.

```php
public static function enumerate (string $body, int $marker, string $subject): array|Failure
```

Uma página de `ListParts` lida depois de `$marker`: `[[number => ['etag' => …, 'size' => …]],
next]`, com `next` `null` na última página. Uma página que repete, pula ou não avança é uma falha
`Protocol`.

```php
public static function frame (array $headers, array $window): int
```

Quantos bytes uma resposta `206` traz para a janela `[offset, length]` pedida, pelo seu
`Content-Range`; `0` quando é outra janela.

```php
public static function fold (array $parts): null|string
```

O ETag que o objeto de um Multipart Upload dessas partes recebe — `"<MD5 dos MD5 binários das
partes, na ordem das partes>-<número de partes>"` — a partir das partes como `Writer::join()` as
recebe (`[número => ['etag' => …]]`). Compare com um `HEAD` da chave para saber se uma conclusão
cuja resposta se perdeu formou o objeto. `null` quando não dá para calcular: nenhuma parte, mais de
10.000, ou um ETag de parte que não tem 32 dígitos hex. Um store cujos ETags de parte não são os MD5
das partes (SSE-KMS, SSE-C, alguns stores compatíveis com S3) ainda pode dar 32 dígitos hex: o fold é
calculado do mesmo jeito, e o ETag do objeto nunca corresponde a ele.

```php
public static function decode (string $body): null|SimpleXMLElement
```

Interpreta uma resposta XML do S3 sem acesso à rede e sem tipo de documento; `null` quando não é
uma.

### S3\Signer

```php
public function __construct (string $key, string $secret, string $region = 'us-east-1', string $service = 's3', string $token = '')
```

Vincula um assinador a um conjunto de credenciais e a um escopo de assinatura. `$token` é o token
de sessão de credenciais temporárias. Lança exceção quando a chave, a região, o serviço ou o
token têm um espaço ou um caractere de controle.

```php
public function sign (string $method, string $host, string $path, array $query, array $headers, string $payload, null|int $time = null): array
```

Assina uma requisição para header auth e retorna os headers a adicionar a ela: `Authorization`,
`x-amz-date`, `x-amz-content-sha256` e, com um token de sessão, `x-amz-security-token`. Todo
header em `$headers` é assinado, então envie todos. `$path` é o path da requisição
percent-encoded, `$host` é o header `Host` como enviado, `$payload` é o SHA-256 do corpo em hex
minúsculo ou `Signer::UNSIGNED`.

```php
public function presign (string $method, string $host, string $path, array $query, int $expires, array $headers = [], null|int $time = null): string
```

Assina uma requisição para query auth e retorna sua query string, com a assinatura por último.
O header `Host` e cada header em `$headers` são assinados — a requisição precisa enviá-los com
aqueles valores — e o payload não.

```php
public static function encode (array $query): string
```

A query string canônica de parâmetros raw: percent-encoded conforme a RFC 3986 e ordenada.

```php
public const string ALGORITHM = 'AWS4-HMAC-SHA256';
```

O algoritmo de assinatura, com o nome que ele tem na requisição.

```php
public const string UNSIGNED = 'UNSIGNED-PAYLOAD';
```

O hash de payload de uma requisição cujo corpo não é coberto pela assinatura — o que o `sign()`
recebe como `$payload` quando o corpo não tem hash.

```php
public const int LIFETIME = 604800;
```

O maior prazo de URL pré-assinada que o Signature Version 4 aceita, em segundos (7 dias): o
limite superior de `$expires` no `presign()`, no `S3::presign()` e no `Uploads::sign()`.

```php
public private(set) string $key
```

O id da chave de acesso.

```php
public private(set) string $region
```

A região de assinatura (`us-east-1`, `auto`, …).

```php
public private(set) string $service
```

O serviço de assinatura (`s3`).

### S3\Writer

```php
public function __construct (string $root, array $options = [])
```

Lê o `root` de um disk (o prefixo de chave) e as opções (`bucket`, `region`, `key`, `secret` e os
opcionais `endpoint`, `path_style`, `token`, `service`, `verify`, `insecure`) como o driver lê.
Lança `InvalidArgumentException` para um transporte inseguro sem `'insecure' => true`, ou uma key,
region, service ou token com um espaço ou um caractere de controle.

```php
public function compose (string $method, string $path, array $query, string $body, array $extra, null|int $time = null): array
```

Uma requisição com autenticação por header: `[URI, headers]` — o path da requisição com a query
canônica, e todo header a enviar: `Host`, os headers da assinatura, depois `$extra`. `Range` e todo
header `x-amz-*` de `$extra` são assinados; todo header vai como foi dado e uma vez só, então um
nome que não é token de header, um valor com quebra de linha ou caractere de controle, um nome dado
duas vezes (em qualquer caixa) e um header que a própria requisição define (`Host`,
`Authorization`, `x-amz-date`, `x-amz-content-sha256`, `x-amz-security-token`, `Content-Length`,
`Transfer-Encoding`, `Connection`) são recusados. Lança `InvalidArgumentException` para esses, e para uma requisição que não pode ir para
a forma canônica.

```php
public function presign (string $method, string $path, int $expires, array $query, array $headers = []): string|Failure
```

A URL pré-assinada de um objeto, ou uma `Refusal` (prazo fora do intervalo, sem credenciais,
endpoint que não é http(s), a raiz do disk, uma requisição que não pode ser assinada). `$query` e
`$headers` não são filtrados aqui: quem os confere é o `S3::presign()`.

```php
public function locate (string $path): string
```

O path de requisição de um path do disk (a raiz permitida): cada segmento da chave
percent-encoded, o bucket primeiro no path style.

```php
public function target (string $path): null|string
```

O path de requisição de um objeto; `null` quando o path aponta a raiz do disk.

```php
public function source (string $path): string
```

O `x-amz-copy-source` de um path do disk: `/{bucket}/{chave codificada}`.

```php
public function resolve (string $path): string
```

A chave do objeto de um path do disk: o prefixo, depois o path normalizado.

```php
public function relativize (string $key): string
```

O path no disk de uma chave armazenada (sem o prefixo).

```php
public function range (int $offset, null|int $length = null): null|string
```

O header `Range` de uma janela (`bytes=offset-last`, ou `bytes=offset-`); `null` quando a janela
não pode ser uma faixa de bytes.

```php
public function describe (array $options): string|array
```

Os headers de objeto de uma escrita a partir das opções `type` e `meta`, ou o motivo de uma delas
não poder ser header (`illegal newline`, `illegal character`).

```php
public function validate (string $step, string $id, int $part = 1): null|Failure
```

`null` quando um upload id e um número de parte podem ir para uma URL, senão uma `Refusal` com o
nome de `$step`.

```php
public function bind (array $headers, bool $part): null|array
```

Os headers que um `PUT` pré-assinado vincula, por nome em minúsculas; `null` quando um não é
permitido, vem duas vezes ou está malformado. Com `$part`, só `Content-Length` e `Content-MD5`.

```php
public function join (array $parts): string|Failure
```

O corpo do `CompleteMultipartUpload` de `[number => ['etag' => …]]`, em ordem crescente de parte,
ou uma `Refusal` para uma lista vazia ou malformada.

```php
public private(set) string $bucket
```

O bucket. `$region` e `$service` são o escopo da assinatura, `$prefix` o prefixo de chave.

```php
public private(set) string $host
```

O host da conexão. `$scheme` é `http` ou `https`, `$port` a porta, e `$authority` o valor de `Host`
para o qual as requisições são assinadas (com a porta, a menos que seja a padrão do scheme).

```php
public private(set) bool $pathStyle
```

Se o bucket é o primeiro segmento do path (path style) em vez de parte do host.

```php
public private(set) bool $verify
```

Se o certificado TLS é verificado.

```php
public string $base
```

O path de requisição do próprio bucket (`/bucket` no path style, senão `/`) — para onde vai uma
listagem ou uma requisição ao bucket.

```php
public null|array $secure
```

As opções TLS de uma conexão (`verify_peer`, `verify_peer_name`, `peer_name`); `null` para `http`.
