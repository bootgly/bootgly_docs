# S3

`S3` is the Storage driver for Amazon S3 and S3-compatible stores (MinIO, Cloudflare R2, Wasabi).
Besides the [Storage](/guide/storage/overview/) contract every disk shares, it has three things of
its own, for bytes that should not travel through your server:

- **presigned URLs** — a link that lets someone read or write one object for a limited time, with
  no credentials;
- **the `Uploads` handle** — a Multipart Upload whose parts a browser sends straight to the bucket;
- **ranged reads** — a window of an object instead of the whole of it.

They are S3 only: reach them on the driver itself, not on the `Storage` facade.

When the bytes do pass through your server — a part it builds or receives — the same handle sends
that part itself. And every call leaves what went wrong on `$S3->Failure`, for code that must
decide what to do next: retry, answer `404`, or give up.

```php
use Bootgly\ABI\Resources\Storage;

$Storage = new Storage([
   'disks' => [
      'media' => [
         'driver' => 's3',
         'root'   => 'uploads',      // every path below is inside this prefix
         'bucket' => 'assets',
         'region' => 'us-east-1',
         'key'    => '…',
         'secret' => '…',
      ],
   ],
]);

/** @var Storage\Drivers\S3 $S3 */
$S3 = $Storage->open('media');
```

Every method below returns `false` when it is refused or fails, leaves the reason on
`$S3->error`, and what went wrong — the status, the store's error code, the kind of failure — on
`$S3->Failure` (see [Branch on a failure](#branch-on-a-failure)). Opening the disk is the exception: it throws `InvalidArgumentException` when a
`key`, `region`, `service` or `token` holds a space or a control character — a trailing newline
read from a secrets file, for one — because those values go into the `Authorization` header and
the query string.

## A time-limited download link

```php
$URL = $S3->presign('GET', 'invoices/2026-11.pdf', 300);
// https://assets.s3.us-east-1.amazonaws.com/uploads/invoices/2026-11.pdf?X-Amz-Algorithm=…

if ($URL === false) {
   // $S3->error says why
}
```

Whoever opens the URL in the next 300 seconds downloads that object — no session, no credentials,
no request through your application. `presign()` makes no request itself: it only signs.

To make the browser save the file under a name, or to fix its type, pass the response overrides.
They are signed with the URL, so the holder cannot change them:

```php
$URL = $S3->presign('GET', 'invoices/2026-11.pdf', 300, [
   'response-content-disposition' => 'attachment; filename="invoice.pdf"',
   'response-content-type' => 'application/pdf',
]);
```

A presigned `PUT` lets the holder store one object in a single request:

```php
$URL = $S3->presign('PUT', 'avatars/42.png', 60);
```

A URL signed like that covers the method, the object and the lifetime — not what is uploaded:
whoever holds it chooses the bytes, their size and their `Content-Type`. To decide them on the
server, bind them as the fifth argument:

```php
$URL = $S3->presign('PUT', 'avatars/42.png', 60, [], [
   'Content-Type' => 'image/png',
   'Content-Length' => 204800,                        // exactly this many bytes
   'Content-MD5' => base64_encode(md5($bytes, true)), // exactly these bytes
   'x-amz-meta-owner' => '42',
]);
```

Each header you bind is signed with the URL: the upload must carry it with exactly that value, or
the store refuses it. Bind only what you need — any subset works:

| Header | What it fixes | What the client sends |
|---|---|---|
| `Content-Length` | The size of the body, in bytes. | Nothing extra: a browser sets it from the body. |
| `Content-Type` | The type the object is stored with. | The same `Content-Type` header. |
| `Content-MD5` | The bytes themselves — the base64 of their MD5. | The same `Content-MD5` header. |
| `x-amz-meta-*` | One metadata entry of the object. | The same header, with the same value. |

From a browser, `Content-MD5`, `x-amz-meta-*` and a `Content-Type` such as `image/png` are
request headers the page sets itself, so the bucket's CORS rule must list them in its allowed
headers. `Content-Length` needs nothing.

> [!WARNING]
> A `PUT` URL with nothing bound is a blank cheque for one object: any bytes, of any size and
> type. Hand it only to code you trust, or bind at least `Content-Length` and `Content-Type`.
> For a large file, use the `Uploads` handle below.

### What a presigned URL is

A presigned URL is a secret that works until it expires. Anyone who reads it — in a log, in a
referrer, in a shared screenshot — can use it. So:

- keep the lifetime short: seconds or minutes, never the 7-day maximum by habit;
- never log it, and never put it in an error message or an exception;
- hand it to the client that asked for it, over HTTPS, and nowhere else.

A URL cannot be revoked one by one: it stops working when it expires, or when the access key
that signed it is disabled.

What it authorizes is narrow by construction:

| | |
|---|---|
| **Method** | `GET`, `HEAD` or `PUT` — the one it was signed for. Deleting, listing and the multipart steps are never presigned here. |
| **Object** | The one path, resolved inside the disk's `root` like every other operation. `../` cannot leave the prefix, and the root itself is refused. |
| **Lifetime** | 1 to 604800 seconds (7 days), counted by the store from the moment of signing. |
| **Query** | Only the six `response-*` overrides, on `GET`/`HEAD`. Anything else — a subresource, an `x-amz-*` parameter — is refused. |
| **Headers** | Only `Content-Type`, `Content-Length`, `Content-MD5` and `x-amz-meta-*`, on `PUT`. Anything else — an ACL, a copy source — is refused. Amazon S3 also rejects an `x-amz-*` header the URL did not sign; check that your S3-compatible store does the same. |

## Upload from the browser straight to the bucket

A large file does not need to pass through your server. The server opens a Multipart Upload,
signs one URL per part, the browser `PUT`s each part to the bucket, and the server joins them.

The handle is `$S3->Uploads`. It keeps no state: an upload spans several requests, so every step
takes the object path and the upload id.

**1. Open the upload** — the server decides the path, the type and the metadata:

```php
$id = $S3->Uploads->create('videos/42/source.mp4', [
   'type' => 'video/mp4',
   'meta' => ['owner' => '42'],
]);
// store $id with your own record of the upload, then send it to the client
```

**2. Sign each part** — as the client asks for them:

```php
$URL = $S3->Uploads->sign('videos/42/source.mp4', $id, $part, 900);   // $part: 1..10000
```

The client sends the bytes of that part with a plain `PUT` to the URL — no headers needed. A
part sent again replaces the earlier one, so a failed part is simply retried.

To fix the size of a part — or its bytes — bind it, as on a presigned `PUT`:

```php
$URL = $S3->Uploads->sign('videos/42/source.mp4', $id, $part, 900, [
   'Content-Length' => 8 * 1024 * 1024,   // this part is exactly 8 MiB
]);
```

A part binds `Content-Length` and `Content-MD5` only: the type and the metadata were set by
`create()`. The last part is usually shorter, so the client says how many bytes it will send
and the server decides whether that size is acceptable before signing.

**3. Check what arrived, then complete:**

```php
$Parts = $S3->Uploads->list('videos/42/source.mp4', $id);
// [1 => ['etag' => '"9b2c…"', 'size' => 8388608], 2 => […], …] — or false

$size = 0;
foreach ($Parts ?: [] as $Part) {
   $size += $Part['size'];
}

if ($Parts === false || $Parts === [] || $size > 2_000_000_000) {
   $S3->Uploads->abort('videos/42/source.mp4', $id);
}
else {
   $S3->Uploads->complete('videos/42/source.mp4', $id, $Parts);
}
```

`list()` is what the store actually holds: the sizes are measured by the store, not reported by
the uploader, and the ETags are the ones `complete()` needs. Completing from `list()` means the
browser never has to read a response header, so the bucket's CORS rules only need to allow the
`PUT` — plus `Content-MD5` as an allowed header, when a part binds it.

**Resume** — `list()` is also how an interrupted upload continues: the parts already there do not
need to be sent again.

**Abort** — an upload that is never completed keeps its parts, and the store bills for them.
Call `abort()` when the user cancels or a check fails, and set a lifecycle rule on the bucket
that aborts incomplete uploads after some days, for the ones nobody cancels.

> [!IMPORTANT]
> Treat the upload id as part of your own state. Keep it on the server next to the record it
> belongs to (who started it, which path), and take the path from that record — never from the
> request. The handle refuses an id that is not a plain token, but it cannot know whose upload
> it is.

### Notes for S3-compatible stores

- **Equal part sizes.** Amazon S3 only requires every part but the last to be at least 5 MiB.
  Cloudflare R2 also requires every part but the last to have the **same** size, and refuses the
  completion otherwise. Pick one part size on the client (8 or 16 MiB, for example), cut the
  file in parts of exactly that size, and check the sizes in `list()` before completing — or
  bind `Content-Length` when signing each part, so no other size can be uploaded.
- **`http` endpoints.** A disk whose `endpoint` is `http://…` (a local MinIO, a test fake) is
  refused at construction unless it sets `'insecure' => true`, and its presigned URLs are `http`
  as well: the URL — a secret — and the bytes travel in clear text. Use it for development only.

## Send a part from the server

Some parts are not in the browser: a part your application builds (a header, a re-encoded
chunk), or one that reached your server anyway. `put()` sends one part of an open upload itself
and returns its ETag:

```php
$ETag = $S3->Uploads->put('videos/42/source.mp4', $id, 3, $bytes);
// '"9b2c…"' — or false: $S3->error and $S3->Failure say why
```

The upload is the one `create()` opened: server parts and browser parts can fill the same upload,
in any order, and `complete()` joins them from `list()` as before — or from the ETags `put()`
returned:

```php
$S3->Uploads->complete('videos/42/source.mp4', $id, [
   1 => ['etag' => $first],
   2 => ['etag' => $second],
]);
```

Some things to keep in mind:

- **Memory.** `$bytes` is a string: the whole part is in memory while it is sent. Keep parts to a
  few MiB (8 or 16 MiB is typical); one part is at most 5 GiB.
- **Size.** Every part but the last must be at least 5 MiB. The store does not check that when
  the part arrives, but at `complete()`, which fails with `EntityTooSmall` on
  `$S3->Failure->code`. On Cloudflare R2 every part but the last must also have the same size.
- **Retries.** A part sent again replaces the earlier one, so a part that failed is simply sent
  again — when `$S3->Failure` says that is worth it (below).
- **Refusals.** An upload id that is not a plain token, a part number outside 1..10000, the disk
  root as path and a body over 5 GiB are refused without a request.

## Read a window of an object

`read()` takes an offset and a length after the sink:

```php
$Sink = fopen('php://memory', 'r+');

$S3->read('videos/42/source.mp4', $Sink, 0, 1024);          // the first 1024 bytes
$S3->read('videos/42/source.mp4', $Sink, 1_048_576, 4096);  // 4096 bytes from offset 1 MiB
$S3->read('videos/42/source.mp4', $Sink, 1_048_576);        // from offset 1 MiB to the end
```

The sink never receives a byte outside the window:

- a window that goes past the end of the object is cut at the end;
- an offset at or past the end is `false` (`range not satisfiable (HTTP 416)`), with nothing
  written;
- an endpoint that ignores the range and answers the whole object, or answers another window, is
  `false`, with nothing written — never the wrong bytes in the sink.

A window can still be cut in transit: the connection drops, or the answer ends before its last
byte. `read()` is then `false` with the first bytes of the window already in the sink. When you
append windows to a file, note the sink's position before each `read()` and truncate back to it
on `false` before retrying:

```php
$position = ftell($Sink);

if ($S3->read('videos/42/source.mp4', $Sink, $offset, $length) === false) {
   ftruncate($Sink, $position);
   fseek($Sink, $position);
   // retry, or give up — $S3->error says why
}
```

With no offset and no length, `read()` is the whole-object read every driver has. The window is
part of `S3::read()` only: `Storage::read()` and the other drivers keep `read($path, $sink)`.

## Branch on a failure

`$S3->error` is a sentence for a log. `$S3->Failure` is the same failure as data, for code that
branches:

```php
use Bootgly\ABI\Resources\Storage\Drivers\S3\Failure\Kinds;

if ($S3->read('invoices/2026-11.pdf', $Sink) === false) {
   $Failure = $S3->Failure;

   if ($Failure->code === 'NoSuchKey') {
      // the object does not exist: answer 404
   }
   else if ($Failure->kind === Kinds::Transport || $Failure->status >= 500 || $Failure->code === 'SlowDown') {
      // the store was unreachable or busy: retry later
   }
   else {
      // refused (access, a bad request): log $S3->error and stop
   }
}
```

A failure has four fields:

| Field | What it holds |
|---|---|
| `status` | The HTTP status of the answer; `0` when no answer arrived, or when nothing was sent. |
| `code` | The store's error code — `NoSuchKey`, `AccessDenied`, `SlowDown`, `EntityTooSmall`, … — or `''` when it gave none. A `HEAD` answer has no body, so a failed `check()`, `measure()` or `inspect()` has a status and no code. |
| `kind` | `Transport`: no complete answer — the endpoint refused the connection, dropped it, timed out or cut the body short. `Protocol`: an answer that is not the one S3 gives — no ETag, no upload id, another range than the one asked for, an answer too large to be S3's. `Refusal`: the store said no — any other status, or an `<Error>` inside a `200` — or the driver refused an input before sending it (status `0`). |
| `message` | The reason of the request that failed, in words. `$S3->error` tells the outcome of the whole call and may word it otherwise: `clear()` says one or more deletes failed, and a request the driver could not sign ends as `HTTP 0` there. |

It never holds the request, the credentials or the store's own `<Message>`: an error body can
echo the signed request, so only its code is kept — and only when it looks like a code (letters,
digits and dots, at most 64).

When it is set:

- **After every call.** `$S3->Failure` is `null` after a call that succeeded, and every call
  starts clean. `check()` of a missing key is `false` with no failure: a `404` is an answer.
- **The first request that failed.** A call made of several requests — a large `write()`, a
  `move()`, a `clear()` — names the first one that failed: the part that was refused, not the
  abort that followed it; the first delete refused, though the ones after it succeeded.
- **Per Fiber.** Requests served concurrently on one disk, each in its own Fiber, each read their
  own failure, even while another Fiber is in the middle of a call. Read it right after the call,
  before the next call on that disk in the same Fiber.
- **Calls inside a call.** A call made on the disk from inside one of its own calls — from a
  stream the disk is reading or writing — belongs to that call: its failure is the outer call's,
  even when the outer call succeeds. Storage event listeners are not inside the call: the facade
  runs them after it, through `preserve()`, and gives the call its `$error` and `$Failure` back.

## Compose and read requests yourself

The driver sends its requests over a blocking socket. Another transport — an HTTP client on an
event loop — can send the very same requests: `S3\Writer` composes them, `S3\Reader` reads the
answers. Neither touches the network.

```php
use Bootgly\ABI\Resources\Storage\Drivers\S3\Operations;
use Bootgly\ABI\Resources\Storage\Drivers\S3\Reader;
use Bootgly\ABI\Resources\Storage\Drivers\S3\Writer;

$Writer = new Writer('uploads', $options);     // the disk's root and options

[$URI, $headers] = $Writer->compose('GET', $Writer->locate('invoices/2026-11.pdf'), [], '', []);
// Send "GET {$URI}" with $headers — Host included — to $Writer->host on $Writer->port,
// over TLS with the $Writer->secure options when it is not null. Then, with the answer:

$Failure = Reader::judge(Operations::GetObject, $status, $answer, $body, "S3 GET {$URI}");
// null: the object is in the body; else the same Failure the driver would give
```

`compose()` signs exactly what the driver signs, so the store sees one client. The writer reads
the options as the driver does — the endpoint, the addressing style, the prefix, the
`insecure` rule — and keeps the credentials inside: a dump of it shows where it points, never
the key or the secret.

## Sign requests yourself

The driver signs with `Storage\Drivers\S3\Signer`, an AWS Signature Version 4 signer you can use
on its own — to call an S3 operation the driver does not wrap, or another service that takes the
same signature:

```php
use Bootgly\ABI\Resources\Storage\Drivers\S3\Signer;

$Signer = new Signer($key, $secret, 'us-east-1');

// Header auth: the headers to send with the request
$headers = $Signer->sign(
   'GET',
   'assets.s3.us-east-1.amazonaws.com',
   '/uploads/a%20b.txt',                 // already percent-encoded
   ['versionId' => '3'],                 // raw: encoded and sorted by the signer
   ['Range' => 'bytes=0-9'],             // signed, and sent by you
   hash('sha256', '')                    // the body's SHA-256
);

// Query auth: the query string of a presigned URL
$query = $Signer->presign('GET', 'assets.s3.us-east-1.amazonaws.com', '/uploads/a%20b.txt', [], 300);
$URL = "https://assets.s3.us-east-1.amazonaws.com/uploads/a%20b.txt?{$query}";
```

The signer signs what it is given: unlike `S3::presign()`, it has no root prefix and no list of
allowed methods or parameters. It throws `InvalidArgumentException` for input that is not
canonical — a line break in the method, the host, the path, a header or the payload hash, a `?`
in the path, a lifetime outside 1..604800, an `X-Amz-*` authentication parameter in the query.
Query values are data: whatever they hold is percent-encoded.

## Reference

### S3

```php
public function presign (string $method, string $path, int $expires, array $query = [], array $headers = []): string|false
```

Presigns one request for an object and returns its absolute URL, without making a request.
`$method` is `GET`, `HEAD` or `PUT`; `$expires` is the lifetime in seconds, 1..604800
(`Signer::LIFETIME`); `$query` takes the `response-content-disposition`, `response-content-type`,
`response-cache-control`, `response-content-encoding`, `response-content-language` and
`response-expires` overrides of a `GET`/`HEAD`, as strings; `$headers` takes what a `PUT` must
send — `Content-Type`, `Content-Length`, `Content-MD5` and `x-amz-meta-*`, each once, as a string
or an integer.
Returns `false` — reason on `$error` — for any other method, parameter or header, a header
value that is empty or malformed, a lifetime out of range, the disk root as path, or a disk
with no `key`/`secret`.

```php
public function read (string $path, $sink, int $offset = 0, null|int $length = null): bool
```

Streams the object — or the window of `$length` bytes starting at `$offset` — into the writable
resource `$sink`. A `null` length reads to the end. Returns `false` for a negative offset, a
length below 1, a missing object, an offset at or past the end, or an answer that is not the
window asked for — with nothing written, when a window was asked for — and for a window cut in
transit, with its first bytes already written.

```php
public private(set) Uploads $Uploads
```

The Multipart Upload handle of the disk.

```php
public null|Failure $Failure
```

The failure of the last call made on the disk in the current Fiber (or outside any Fiber):
`null` after a call that succeeded. A call made of several requests names the first one that
failed. Read-only.

```php
public function preserve (Closure $Work): void
```

Runs `$Work` and gives the disk back the outcome of the call made before it: `$error` and
`$Failure` read after `$Work` what they read before. The Storage facade runs its event listeners
here. `$Failure` is given back in the current Fiber; `$error` is one per disk, shared by every
Fiber, so concurrent code reads `$Failure`.

### S3\Uploads

```php
public function create (string $path, array $options = []): string|false
```

Starts a Multipart Upload for the object and returns its upload id. `$options` are the write
options: `type` (Content-Type) and `meta` (a `x-amz-meta-*` map).

```php
public function sign (string $path, string $id, int $part, int $expires, array $headers = []): string|false
```

Presigns the `PUT` of one part (1..10000, `Uploads::PARTS`) of that upload and returns its URL,
without making a request. `$expires` is the lifetime in seconds, 1..604800 (`Signer::LIFETIME`);
`$headers` takes what the `PUT` must send — `Content-Length` and `Content-MD5`, each once.
Returns `false` for any other header.

```php
public function put (string $path, string $id, int $part, string $body): string|false
```

Sends part `$part` (1..10000) of the upload with `$body` as its bytes and returns its ETag, as the
store sent it (quoted). The part replaces any earlier one with the same number. Returns `false`
for an invalid upload id or part number, the disk root as path, a body over 5 GiB, or a failed
request — reason on `$error`, details on `$Failure`. The handle the driver builds always has
this step; a handle built by hand without it throws `LogicException`.

```php
public function list (string $path, string $id): array|false
```

Lists every part the store holds for the upload, following every page:
`[number => ['etag' => string, 'size' => int]]`, ascending. Returns `false` when any page fails
or is malformed — never a partial list.

```php
public function complete (string $path, string $id, array $parts): bool
```

Joins the parts into the object. `$parts` is what `list()` returns, or
`[number => ['etag' => …]]` built from the ETags the uploader received. A failed completion
leaves the upload open: complete again, or abort.

```php
public function abort (string $path, string $id): bool
```

Aborts the upload and releases its parts. An upload the store no longer knows counts as aborted.

```php
public const int PARTS = 10000;
```

The most parts one upload holds, and the highest part number.

### S3\Failure

```php
public private(set) int $status
```

The HTTP status of the answer; `0` when no answer arrived or nothing was sent.

```php
public private(set) string $code
```

The store's error code (`NoSuchKey`, `AccessDenied`, `SlowDown`, …); `''` when it gave none, or
gave something that is not a code.

```php
public private(set) Failure\Kinds $kind
```

`Transport`, `Protocol` or `Refusal`.

```php
public private(set) string $message
```

The reason of the request that failed, in words. `$error` tells the outcome of the whole call
and may word it otherwise (a later step that failed too, or the `HTTP 0` of a request that could
not be signed).

### S3\Failure\Kinds

```php
enum Kinds { case Transport; case Protocol; case Refusal; }
```

How a request failed: no complete answer (`Transport`), an answer that is not the one S3 gives
(`Protocol`), or a no from the store or from the driver itself (`Refusal`).

### S3\Operations

```php
enum Operations
```

The S3 operations the driver sends, each with its own success answers for `Reader::judge()`:
`PutObject`, `GetObject`, `HeadObject`, `DeleteObject`, `CopyObject`, `ListObjectsV2`,
`CreateMultipartUpload`, `UploadPart`, `ListParts`, `CompleteMultipartUpload`,
`AbortMultipartUpload`.

### S3\Reader

```php
public static function judge (Operations $Operation, int $status, array $headers, string $body, string $subject, null|array $window = null): null|Failure
```

`null` when the answer is the success of `$Operation`, else its failure. `PutObject`,
`CreateMultipartUpload` and `UploadPart` succeed on any `2xx`; `CopyObject` and
`CompleteMultipartUpload` on a `2xx` without an `<Error>`; `GetObject` on a `200` — or, with a
`$window` (`[offset, length]`), a `206` of that window; `HeadObject`, `ListObjectsV2` and
`ListParts` on a `200`; `DeleteObject` and `AbortMultipartUpload` on `200`, `204` or a `404` that
says what is gone is gone (an empty or blank body, `NoSuchKey`, `NoSuchUpload`) — never another `404`
(`NoSuchBucket`, a proxy's page).
`$headers` have lowercase names; `$subject` starts the message (`S3 GET /bucket/key`).

```php
public static function identify (string $body, string $subject): string|Failure
```

The upload id of a `CreateMultipartUpload` answer, or a `Protocol` failure.

```php
public static function tag (array $headers, string $subject): string|Failure
```

The ETag of an `UploadPart` answer, as sent, or a `Protocol` failure when it is missing or could
not be sent back to `complete()`.

```php
public static function index (string $body, array $followed, string $subject): array|Failure
```

One `ListObjectsV2` page: `[keys, next]`, where `next` is the next continuation token, `''` on
the last page, or a `Protocol` failure when the page does not advance (no token, or one in
`$followed`). A body that is not a listing is a `Protocol` failure.

```php
public static function enumerate (string $body, int $marker, string $subject): array|Failure
```

One `ListParts` page read after `$marker`: `[[number => ['etag' => …, 'size' => …]], next]`, with
`next` `null` on the last page. A page that repeats, skips or does not advance is a `Protocol`
failure.

```php
public static function frame (array $headers, array $window): int
```

How many bytes a `206` answer carries for the window `[offset, length]` asked for, from its
`Content-Range`; `0` when it is another window.

```php
public static function decode (string $body): null|SimpleXMLElement
```

Parses an S3 XML answer with no network access and no document type; `null` when it is not one.

### S3\Signer

```php
public function __construct (string $key, string $secret, string $region = 'us-east-1', string $service = 's3', string $token = '')
```

Binds a signer to one set of credentials and one signing scope. `$token` is the session token of
temporary credentials. Throws when the key, region, service or token holds a space or a control
character.

```php
public function sign (string $method, string $host, string $path, array $query, array $headers, string $payload, null|int $time = null): array
```

Signs a request for header auth and returns the headers to add to it: `Authorization`,
`x-amz-date`, `x-amz-content-sha256` and, with a session token, `x-amz-security-token`. Every
header in `$headers` is signed, so send them all. `$path` is the percent-encoded request path,
`$host` the `Host` header as sent, `$payload` the lowercase hex SHA-256 of the body or
`Signer::UNSIGNED`.

```php
public function presign (string $method, string $host, string $path, array $query, int $expires, array $headers = [], null|int $time = null): string
```

Signs a request for query auth and returns its query string, the signature last. The `Host`
header and every header in `$headers` are signed — the request must send them with those
values — and the payload is not.

```php
public static function encode (array $query): string
```

The canonical query string of raw parameters: percent-encoded per RFC 3986 and sorted.


The signing algorithm, as it is named on the wire.


The payload hash of a request whose body is not covered by the signature — what `sign()` takes

### S3\Writer

```php
public function __construct (string $root, array $options = [])
```

Reads a disk's `root` (the key prefix) and options (`bucket`, `region`, `key`, `secret`, and the
optional `endpoint`, `path_style`, `token`, `service`, `verify`, `insecure`) as the driver does.
Throws `InvalidArgumentException` for an insecure transport without `'insecure' => true`, or a
key, region, service or token holding a space or a control character.

```php
public function compose (string $method, string $path, array $query, string $body, array $extra, null|int $time = null): array
```

One request for header auth: `[URI, headers]` — the request path with its canonical query, and
every header to send: `Host`, the signature headers, then `$extra`. `Range` and every `x-amz-*`
header of `$extra` are signed; every header is sent as given and once, so a name that is not a
header token, a value with a line break or a control character, a name given twice (in any letter
case), and a header the request sets itself (`Host`, `Authorization`, `x-amz-date`,
`x-amz-content-sha256`, `x-amz-security-token`, `Content-Length`, `Transfer-Encoding`,
`Connection`) are refused.
Throws `InvalidArgumentException` for those, and for a request that cannot be put in canonical
form.

```php
public function presign (string $method, string $path, int $expires, array $query, array $headers = []): string|Failure
```

The presigned URL of one object, or a `Refusal` (a lifetime out of range, no credentials, an
endpoint that is not http(s), the disk root, a request that cannot be signed). `$query` and
`$headers` are not filtered here: `S3::presign()` is the call that checks them.
